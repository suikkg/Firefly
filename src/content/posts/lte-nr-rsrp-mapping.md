拿到一份终端 log，看到 `RSRP = 33`，这个信号强度到底是多少 dBm？

如果答案是 "33 就是 -108"，那大概率是拿 LTE 的映射表在算；如果按 NR 来算，同样是 33，结果却是 -124。同一个上报值，两种结论相差 16 dB，而 16 dB 在覆盖评估里几乎是"有信号"和"没信号"的差别。

这篇文章把 LTE 和 NR 两套 RSRP 上报编码从头到尾对一遍，包括 L1/L3 的区别、"index 减 141 / 减 157"这两个换算常数的由来，以及几个容易混淆的点。所有表格内容均核对自 3GPP 规范原文（36.133 / 38.133 / 38.214 / 38.331，Release 19 版本）。

## 一、先看规范怎么定义上报范围

LTE 的 RSRP 上报映射定义在 **TS 36.133 §9.1.4**，NR 的定义在 **TS 38.133 §10.1.6**。两份规范的报告范围声明如下：

| 规范 | 章节 | 报告范围声明 | 分辨率 |
|---|---|---|---|
| 36.133（LTE） | §9.1.4 | -156 ~ -44 dBm | 1 dB |
| 38.133（NR L3） | §10.1.6 | -156 ~ -31 dBm | 1 dB |
| 38.133（NR L1） | §10.1.6 | -140 ~ -44 dBm | 1 dB |

注意 36.133 在最新版（v19.x）里，正文已经写成 "-156 ~ -44 dBm"。但范围声明不等于编码起点，这一点后面会专门讲。

## 二、LTE 的 RSRP 映射（36.133 表 9.1.4-1）

LTE 的映射表实际内容如下（v19.4.0 / v19.5.0 核对一致）：

| 上报值 | 测量量 | 单位 |
|---|---|---|
| RSRP_-17 | RSRP < -156 | dBm |
| RSRP_-16 | -156 ≤ RSRP < -155 | dBm |
| … | … | … |
| RSRP_-01 | -141 ≤ RSRP < -140 | dBm |
| RSRP_00 | RSRP < -140 | dBm |
| **RSRP_01** | **-140 ≤ RSRP < -139** | dBm |
| RSRP_02 | -139 ≤ RSRP < -138 | dBm |
| … | … | … |
| RSRP_96 | -45 ≤ RSRP < -44 | dBm |
| RSRP_97 | -44 ≤ RSRP | dBm |

关键点：

1. **正下标区的锚点是 RSRP_01 = -140 dBm**。这是 LTE 一直以来没变的编码起点。
2. v19 新增了 **RSRP_-17 ~ RSRP_-01** 这一组负下标，把范围向下扩展到了 -156 dBm。注意 RSRP_00 仍然是 "RSRP < -140"（无下界兜底），负下标只是对 -156 ~ -140 这一段的细分。
3. 因此 LTE 的换算公式：

```
dBm = index - 141
```

例如 `RSRP_33 = 33 - 141 = -108 dBm`，`RSRP_97 = 97 - 141 = -44 dBm`。注意这里的 **141 是"要减掉的常数"（锚点 -140 减去下标偏移 1），不是编码起点**——LTE 的起点始终是 -140 dBm。

## 三、NR 的 RSRP 映射（38.133 表 10.1.6.1-1）

NR 的这张表是**双列结构**，L3 和 L1 共用同一组行号：

| 上报值 | L3 SS-RSRP / CSI-RSRP | L1 SS-RSRP / CSI-RSRP |
|---|---|---|
| RSRP_0 | SS-RSRP < -156 | Not valid |
| RSRP_1 | -156 ≤ SS-RSRP < -155 | Not valid |
| … | … | … |
| RSRP_15 | -142 ≤ SS-RSRP < -141 | Not valid |
| RSRP_16 | -141 ≤ SS-RSRP < -140 | RSRP < -140 |
| **RSRP_17** | **-140 ≤ SS-RSRP < -139** | **-140 ≤ RSRP < -139** |
| RSRP_18 | -139 ≤ SS-RSRP < -138 | -139 ≤ RSRP < -138 |
| … | … | … |
| RSRP_33 | -124 ≤ SS-RSRP < -123 | -124 ≤ RSRP < -123 |
| … | … | … |
| RSRP_113 | -44 ≤ SS-RSRP < -43 | -44 ≤ RSRP |
| RSRP_114 | -43 ≤ SS-RSRP < -42 | Not valid |
| … | … | … |
| RSRP_126 | -31 ≤ SS-RSRP | Not valid |

两个容易搞错的地方：

1. **L3 列锚点是 RSRP_1 = -156 dBm**，所以 NR L3 的公式是 `dBm = index - 157`。`RSRP_33 = 33 - 157 = -124 dBm`。
2. **L1 列并不是从 -140 的 index 1 开始**。L1 列虽然范围是 -140 ~ -44，但它的 -140 落在 **RSRP_17** 这一行（与 L3 对齐）。也就是说 L1 列的换算公式同样是 `dBm = index - 157`，`RSRP_33` 在 L1 列也是 -124 dBm。

这里有个反直觉的结论：**NR 的 L1 和 L3，同一个 index 对应的 dBm 是一样的**（从 RSRP_17 起）。"L1 锚点 -140" 指的是它的测量范围下限是 -140 dBm，而不是说 index 33 应该按 -140 起算。真正按 -140 起算（index 1 = -140）的只有 LTE。

## 四、三个容易混的坑

### 坑 1：把减法常数 157 当成编码起点 -157

网上不少资料写 "NR RSRP 从 -157 开始"，这是错的。规范的锚点是 **RSRP_1 = -156 dBm**；换算时 index 减掉的常数是 **157**（正数），编码起点却是 **-156 dBm**（负数）。写文章、写测试用例的时候，锚点写 -156，换算写 `index - 157`，别混。

### 坑 2：看到 -140 就以为是 LTE

NR 的 L1 RSRP 范围下限也是 -140 dBm，所以"起点 -140 = LTE"这个判断在 L1 场景下会翻车。正确的判断顺序是：

```
看到 RSRP = 33
  ├── LTE（36.133 RSRP-Result）→ 33 - 141 = -108 dBm
  ├── NR L3（38.133 SS-RSRP）→ 33 - 157 = -124 dBm
  └── NR L1（38.214 L1-RSRP 上报）→ 先确认字段编码，再换算
```

### 坑 3：把 38.133 表的行号和 38.214 的上报字段当成一回事

38.214 §5.2.1.4.3 定义的 L1-RSRP 上报是 **7-bit 独立编码**，范围 [-140, -44] dBm，1 dB 步进；多波束场景下最大值为 7-bit 绝对量，其余用 4-bit 差分（2 dB 步进，0 ~ -30 dB）。这个 7-bit 字段的 index 和 38.133 表 10.1.6.1-1 的行号不是同一个东西。所以 log 里看到 L1-RSRP 字段的值，不能直接套 38.133 的行号换算，先确认它出自哪个 IE。

## 五、L1 和 L3 的 RSRP 到底差在哪

既然数值映射一样，L1 和 L3 的差异就在测量与报告流程上：

| | L3 RSRP | L1 RSRP |
|---|---|---|
| 报告层 | RRC 测量报告（MeasurementReport） | 物理层上报（CSI / L1 measurement reporting） |
| 粒度 | 小区级 | 波束级（每个 SSB / CSI-RS 波束） |
| 滤波 | 经过 L3 滤波（38.331 §5.5.3.2） | 无 L3 滤波 |
| 范围 | -156 ~ -31 dBm（L3 列） | -140 ~ -44 dBm（L1 列） |
| 用途 | 小区选择/重选、切换、覆盖评估 | 波束管理、BFR、fast SCell activation、LTM |

L3 的测量值不是凭空来的。按 38.331 §5.5.3 的链路：

```
物理层测量各波束 RSRP（38.215）
  → 波束合并成小区级 RSRP（§5.5.3.3：取最高波束，或对超过合并阈值的若干波束做线性平均）
  → L3 滤波（§5.5.3.2，filterCoefficient 指数平滑）
  → 事件评估 / 上报
```

也就是说，L3 值源自 L1 的波束测量，但经过了"波束合并 + L3 滤波"的加工。日常看信号强度（覆盖、切换、路测）看 L3 就够；只有在调波束、查 BFR / LTM / SCell 激活这类问题时才需要翻 L1。

## 六、速记总结

| 场景 | 换算公式 | index 33 |
|---|---|---|
| LTE RSRP（36.133） | `index - 141` | **-108 dBm** |
| NR L3 SS-RSRP（38.133） | `index - 157` | **-124 dBm** |
| NR L1（38.133 表 L1 列） | `index - 157` | **-124 dBm** |
| NR L1（38.214 7-bit 上报字段） | 独立编码，看具体 IE | 视字段而定 |

最后再强调一次：**判断一个 RSRP 上报值是多少 dBm，先确定三件事——哪个 RAT、哪个测量量（L3 还是 L1）、哪个 IE 的编码**，然后再套公式。光看数字本身，不确认 LTE 减 141 还是 NR 减 157，是算不出正确答案的。
